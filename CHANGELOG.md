## [Unreleased]

### Added
- **Screen / feature wiki** (`docs/plans/wiki-metadata.md`).
  - Projects keep a map of what is built in `docs/wiki/`: `screens/<slug>.md` (route, files, components used, APIs, states, `links_to`) and `features/<slug>.md` (the screens of one user flow), with a short body (role, composition, caveats).
  - `scripts/wiki.js`: `check` (status `ok` / `stale` / `unstamped` / `broken` / `invalid`; `--strict` exits 1), `stamp` (hash of the listed files — for a feature also the files of its screens, so it goes stale with them; refuses files outside the project, symlinks and invalid pages, and then writes nothing), `index` (rewrites `index.md`), `find` (route / component / API / file search with page status). It writes only `.md` files inside `docs/wiki/`; a symlinked `docs/wiki` is refused. Page text is untrusted data: control characters and items over 300 characters make a page `invalid`, and the guides say never to follow instructions found in a page.
  - `/wiki init` (first build after the user confirms the screen list), `/wiki update`, `/wiki check`; guide `memory/reference_wiki.md`.
  - `/plan` looks up existing screens in the wiki before searching the code and refreshes pages that are not `ok` first; it suggests `/wiki init` when a project with screens has no wiki. `phase_end.md` updates and stamps the pages of changed screens. Publisher briefing and publisher Step 2 pick reference screens and reuse anchors from the wiki; publisher never edits it.
  - Tests in `test/wiki.test.js` (`npm test` runs both suites).
- **Replay rounds and a dead-control sweep script** (`docs/plans/tc-replay.md`).
  - `scripts/tc-replay.js`:
    - e2e-tester writes each TC it runs (`record: true`) as data — a fixed list of ops (`goto` / `click` / `fill` / `select` / `check_box` / `press` / `wait` / `capture` / `request`) and one check per expected result — in `.cc-audits/<plan>/replay/<tc>.json`. A recording is never code.
    - `check` validates a recording against its TC: one entry per step and per expected result, the check kind matching the `observe.channel`, paths only on `base_url`, `{{data.x}}` / `{{captured}}` / integer `+ -` templates, `$ENV` only for `secret_env` names, no nested-quantifier regexes, `tc_file` under `docs/tc/`.
    - `run --verify` replays a recording on the tester's code and compares every verdict, `failed_at_step` and the invariants with the tester's line. Equal → `accepted`, else `rejected`. Results Jev left as REVIEW are kept as `unverified`.
    - Acceptance lives only in `replay-accepted.json`. A changed recording is no longer accepted; `--retry-rejected` re-verifies after an outside cause is fixed.
    - `run` replays accepted recordings for a round and writes `tc-results.jsonl` lines (`browser_tool: replay`) with code verdicts, `failed_at_step` when a step's done check fails, `invariants` against the tester's baseline of allowed 4xx / console errors, and `sweep`.
    - A replay that cannot find its controls, a stale TC digest, or a missing or unaccepted recording gives `fallback` with no line — that TC goes back to a tester.
    - Jev REVIEW or re-check results come back `pending`; the manager judges the observation file and runs `finish`.
    - Checks: `text` / `count` / `visible` / `hidden` / `enabled` / `disabled` / `value` / `url_path` / `url`; `api` (a saved response, or its own GET / HEAD); `db` (value or `count`, also from a capture); `log_count`. Comparisons: `equals` / `includes` / `starts` / `excludes`, plus `all_equals` / `in` / `not_in` with `field` for lists.
    - A request under the recording's session uses the browser's login, so a reset server does not leave it signed out.
  - `scripts/tc-sweep.js`:
    - The dead-control sweep (§0-B) in code, used by testers on every screen and by replays on the screens they visit.
    - It opens each path fresh per control, waits for the network to settle, and clicks every visible control (same-looking controls each once).
    - A control with no effect — no navigation, popup, request, DOM change or dialog — or a page error is `fail`.
    - Requests other than GET / HEAD are aborted, so a sweep never changes data. Destructive-looking controls (word-bounded `delete` / `pay` / `logout`… and `삭제` / `결제`…) are skipped.
    - Disabled, re-rendered or unclickable controls are skipped, not failed. Controls that appear after a click are swept unless the click moved to another view.
    - Results go to `.cc-audits/<plan>/sweep/<run_id>/` (one file per URL, so parallel testers never overwrite each other).
    - Browser contexts are limited to `base_url`'s origin; service workers and off-origin WebSockets are blocked.
  - `tc-run.json` gains `reset_command` (same `node <project script> <args>` form as `*_command`), run before every round and every verify replay.
  - The manager guide adds §2-C (replay rounds); e2e-tester gains a Recording section, sweeps with `tc-sweep.js`, and records `invariants` / `sweep` on each TC line.
  - `--doctor` gains `Replay browser`: a Playwright module for the replay and the sweep (the one inside `@playwright/mcp` is enough; `CC_BASELINE_PLAYWRIGHT` overrides).
  - `tc-jev-judge.js record` refuses a `failed_at_step` that is not a 0-based step index. `tc-api-run.js read` also refuses `replay-state/`, `replay-pending/` and `obs/`.
  - Sample app (fix loop on 9 TCs, 4 seeded defects): done in 3 rounds, the last one fully replayed (90 s with sweep, no LLM tokens). The whole loop cost about 580k tokens against about 1.2M for tester-only rounds.
- **Stage-2 TC fix loop** (`docs/plans/tc-fix-loop.md`).
  - `scripts/tc-fix-loop.js`:
    - Keeps the loop state in `.cc-audits/<plan>/findings.json`.
    - `next` tells the manager what to do: `run_round` / `wait_results` / `classify` / `fix` / `cap_reached` / `final_regression` / `ask_user` / `done`, with an `ask_user` list alongside.
    - `start` freezes the ready, non-skipped TCs (digest). A round is refused when TC text changed without `tc-change` (the user's OK and a reason). A TC removed with the user's OK leaves the loop through `tc-change`.
    - Every failure gets one class: `product` / `env` / `fixture` / `runner` / `case` / `decision`. Only `product` gets a `fix`, which needs a repro test path or `--test none:<reason>`; the other classes go to the user while the rest of the loop goes on (`resume` brings a TC back).
    - The same failure fingerprint (failed step + failing expected indices, plus `invariants` / `sweep` fails) after a fix marks the TC `stuck`.
    - Limits come from `tc-run.json` → `loop` (defaults 3 fixes per TC, 5 rounds; the closing full round may go one past). After partial re-runs pass, one full round runs before `done`; a TC that passed earlier and fails now is listed as a regression.
    - `accept` takes a NOT_OBSERVABLE result as passed with a reason, `no-result` closes a TC the runner left without a line, and `report` sums rounds, fixes, classes, time and Jev cost.
  - The manager guide adds §2-B (the loop, the class table, fix rules: repro test first, never branch on TC data, never touch `docs/tc/`). `/plan` and the TC authoring guide point to it.
  - Sample app (9 TCs, 4 seeded defects): done in 4 rounds; `case` → `ask_user`, `stuck` and `final_regression` all seen.
- **TC/Jev stage 2: Jev as the judge, a sample bank, an API TC runner** (`docs/plans/tc-jev-loop.md`).
  - `scripts/tc-jev-judge.js`: a calibrated question × model is decided by Jev; about 10% of its verdicts (fixed by request digest) come back `audit: true` and the tester re-checks them with its own judgment (`audit --sample --llm`). Two disagreements in the last 20 re-checks since calibration revoke the entry automatically (`calibration.json` → `revoked`); applying a calibration still needs the user. Samples are split 70/30 `calib` / `holdout` by digest, and `calibrate` proposes on `calib` and must also hold on `holdout` (else `unsafe`). New `label --sample --label human:PASS|FAIL` (review queue), `bank` (per-question counts per split, review queue, re-check record, calibration state) and `bank --export <dir>` (private copy, refused inside a git work tree unless ignored). `record` accepts a `run_id`.
  - `scripts/tc-api-run.js`: the tester's only way to send API requests and read project data for `api` / `db` / `log` expected results. `request` sends to `base_url`'s origin only (paths only, redirects reported not followed, a non-loopback `base_url` needs `api_remote_ok: true`), keeps a cookie jar per `--session` (0600), fills `$ENV` body values, and masks cookies, auth headers, tokens and secret values; `read` opens only the run file's `readable` files inside the project root (`--json-path a.b[k=v].c` or `--grep`). Output capped at 64 KB.
  - `/plan`: TCs are drafted in the plan (`## Test Cases (draft)`), checked from stdin (`tc-lint.js -`, `tc-jev-check.js -`), open questions are asked with AskUserQuestion before approval, and the TC file and `tc-run.json` are written right after approval — plan mode stays read-only. `open_questions` gets a defined shape (`id`, `question`, `default`, `affects`, `answer?`, `decided_at?`) checked by `tc-lint.js`, which also allows a per-expected-result `basis`.
  - First sample-app round with e2e-tester agents: expected results are numbered from 0 everywhere; a 4xx the TC itself expects is not an invariant failure; sweeps skip data-changing controls as `skipped (mutating)`; testers judge from the screen and `tc-api-run.js` only, never from the product's source; observation files carry `channel`, and `judge --label` refuses `api` / `db` / `log` samples. `tc-api-run.js read` accepts `[k=v,k2=v2]` filters, dots inside a value, and `--count`. `tc-check.json` keeps a `by_file` block per TC file when one plan has several.
  - Sample-app rounds R1–R8 (results in the plan): `tc-jev-judge.js judge --judge-mode jev --label code:PASS|FAIL` lets a calibrated Jev decide screen results the code also checks, keeping `code_verdict` and `agree_with_code` (V11 experiment; `code` stays the default); `record` accepts `judge_mode` and `code_verdict`; new `compare --results --run-id …` tables runs by who decided and agreement with code. `tc-api-run.js read` takes repeated `--grep` (lines containing every text). e2e-tester: a failing TC stops only itself; fail logs are read through `tc-api-run.js` and never used for a verdict; a step may run the run file's `*_command`; api logins use `tc.run.api.login_path` (never guessed); observations cover the region the expected result names (menu, dialogs, status) and carry `item` for target rows. TC authoring: `done_when` must be checkable even when the feature is broken.
  - Follow-ups: `calibrate` adds a `warning` to an `ok` report whose samples all come from one project; `judge` reports `observation_gaps` when the expected result names the menu but the observation has no banner / navigation, or points at a target without `item` — a labelled sample with a gap is not stored (`status: needs_fix`); `record` accepts `jev_ms` / `jev_tokens` and `compare` sums them per run; `tc-lint` warns on a `done_when` that only says the screen is redrawn / updated.
  - Security review of stage 2: `tc-api-run.js` accepts only a run file at `<project>/.cc-audits/<slug>/tc-run.json` (the `project_dir` fallback is gone), fills `$NAME` body values only for names a TC lists in `secret_env`, reads `--body` only from the temp dir or the project, never reads `.env*`, key files, `.git/`, `.ssh/` or `api-sessions/` (also through symlinks), masks values of secret-named fields (`password`, `token`, `secret`, `api_key`, …), and refuses an empty `--grep`. `tc-jev-judge.js audit` accepts only a verdict marked `audit: true` and counts each sample once (a screen re-checked before returns that earlier re-check, `already_rechecked: true`); testers never run `label`. A step's `*_command` must be `node <project script> <plain args>`, shown to the user at plan approval. `judge --judge-mode jev` keeps `code_verdict` on error / unconfigured / loading results; `compare` reports an unknown `run_id` and a missing results file.
  - e2e: `api` TCs run on one tester after the screen TCs instead of `skip: api-only`; observations go to `obs/<tc>/<run_id>/` so re-runs keep earlier evidence; the manager offers the review queue to the user after a run.

### Fixed
- The dead-control sweep (`tc-sweep.js`) judged badly on real pages (`docs/plans/tc-replay.md`).
  - On a page that changes on its own (animations, typing effects), every click counted as "effect", so dead controls passed. It now watches the page for 600 ms before each click; nodes, requests and scrollers that change then are noise. A dead control on such a page still fails, with the reason `page changes on its own: N nodes`. Scrolling now counts as an effect.
  - A modal that opens on load (a notice shown on every fresh tab) covered the page, so the controls behind it were never clicked. It is dismissed first — Escape, else a close-like button inside it (never a destructive-looking one) — and reported as `startup_overlay`. A page mostly covered by a dialog it could not close gets `hint`.
  - A click that saved state (a language toggle in localStorage) changed every later open, and the controls whose names changed were dropped without a trace. Every reopen now starts from the first open's cookies and localStorage, and a control still missing is listed as `gone after reopening`.
  - Faster: the network-idle wait is at most 1 s and the render wait (3 s at most) ends when only already-changing nodes still change. On a real landing page (Next.js, WebGL hero, beta-notice modal) the sweep went from 0 controls clicked (20 covered, 185 s, time budget hit) to 19 clicked in 90 s, no false failures.
- Verify replays accepted a recording whose FAIL had another cause than the tester's (`docs/plans/tc-replay.md`). On a real Next.js + Supabase project the tester saw `0` because the app's CSP blocked Supabase, the replay saw `0` because the replayer itself blocked that origin, and the recording was accepted.
  - `run --verify` now also compares the `observed` value where both sides FAIL a code check (the tester's value must start with the replay's; a note after it is allowed), and rejects a failing replay that blocked requests outside `base_url` / `browser_origins`.
  - In rounds, a failing replay that blocked such requests writes no line and falls back (`blocked_offsite:<origins>`). A passing one is recorded as before.
  - e2e-tester writes a code result's `observed` as the value first, notes after it in parentheses.
- Replay and sweep on a real project (Next.js + Supabase): `tc-run.json` `browser_origins` lists extra https origins the app's browser code must reach; api checks can test a response header; invariants are judged after in-flight requests finish (up to 3 s); the sweep has per-step timeouts, a 3-minute page budget, a DOM-settle wait, a retry before calling a control dead, skips covered controls, and drops page-to-server WebSocket frames (`CC_SWEEP_DEBUG=1` for diagnostics). Known limit: on pages whose DOM changes constantly the sweep cannot tell a dead control from a live one.
- `/clean` no longer kills the session that runs it, nor a claude still attached to a terminal. The orphan step matched any process whose arguments contained "claude" with parent PID 1 — a `tmux -L claude` server hosting the session, or the session itself in a container — and stopped it. It now matches only the `claude` executable and the npm install (like the SessionEnd hook), skips every ancestor of the running shell and headless `-p` / `--print` runs, and uses POSIX `[ ]` so `/bin/sh` can run it.
- `tc-jev-check.js` warned `jev_hidden` on lines already read from an `api` / `db` / `log` / `artifact` / `env` channel (29 false warnings on a 41-line TC file).
- Playwright MCP could not open a browser when Claude Code runs as root on Linux (Chromium sandbox). The installer adds `--no-sandbox` to `playwright-test-*` there, `--doctor` warns when it is missing, and on Linux without `/opt/google/chrome/chrome` the installer prints `npx playwright install --with-deps chrome`.
- Linux semgrep install reported `✅ semgrep installed` when it had failed: the venv path ran `python3 -m venv` and both `pip` steps without checking their exit status, so a Python without the `venv` module (stock Ubuntu without `python3-venv`) left a half-built venv and a dangling `~/.local/bin/semgrep` link. Every step is now checked, `semgrep --version` must run before the link is made, and a failed run removes the venv and the dangling link and names the missing package.
- Linux gitleaks install always failed with a 404: it downloaded `checksums.txt`, but gitleaks publishes `gitleaks_<ver>_checksums.txt`.
- `--doctor` warned "notify-send not found" on headless Linux (SSH or Remote Control servers), where no desktop exists to show a notification. With neither `DISPLAY` nor `WAYLAND_DISPLAY` set it now reports notifications as not applicable instead.
- README / README_KO and `docs/install-details.md` (en/ko) caught up with v1.6.0: design-director agent and Aside session helper added to the feature list and component table, publisher's Aside-first verification and Web Interface Guidelines self-check described, the version-pin example points at `#v1.6.0`, and the file-install matrix lists all 27 overwrite files (it had stopped at 18) and the pinned `@playwright/mcp@0.0.75` instead of `@latest`.
- `reference_design_md_index.md`: 19 catalog one-liners corrected against the pinned DESIGN.md files they point to. design-director shortlists from these lines alone, so a wrong line steered it to the wrong candidates: ten entries were described as dark when their DESIGN.md is a light or cream canvas (`elevenlabs`, `minimax`, `opencode.ai`, `cursor`, `expo`, `cohere`, `posthog`, `supabase`, `kraken`, `bmw`), five had the wrong color, type or identity (`mistral.ai` is orange not purple, `intercom` cream/orange not blue, `notion` sans not serif headings, `shopify` has no neon green, `clay` is a GTM data platform not a creative agency), and four were only partly right (`superhuman`, `sentry`, `hashicorp`, `together.ai`). `clay` also moved from Design & Creative Tools to Productivity & SaaS and gained the `product-ui` lane, since its DESIGN.md documents product mockup cards, enrichment tables, inputs and tabs; the catalog now lists 43 entries usable for `product-ui`.

## [1.6.0] — 2026-11-05

### Added
- **Aside as the primary browser tool, Playwright MCP as the fallback** (`docs/plans/browser-aside-e2e-fixes.md`). e2e-tester, publisher Step 6, `/open-browser` and `/check-log` now drive [Aside](https://aside.com) through its CLI (`aside repl --account <test account>`) and switch once to the existing `playwright-test-*` servers when Aside is missing, has no test account, or fails the same step twice; every report records `BROWSER_TOOL` / `FALLBACK_REASON`. Aside runs only under the account set in `cc-baseline-browser.json`, never the user's personal profile.
  - `templates/memory/reference_browser_tools.md` — tool choice, switch conditions, and how to drive Aside. Measured limits are written down rather than assumed: a single `aside repl "<code>"` call is a fresh session (tabs close on return); console / page-error / response events are not delivered, so a page-side `__e2e` recorder (console.error, `error`, `unhandledrejection`, fetch/XHR ≥ 400) is injected after every navigation; `page.goto` returns no response; screenshots can only be written inside the session dir; `addInitScript` and code containing `import(` are rejected; REPL `fetch()` exposes `Set-Cookie`, so replays are redacted.
  - `templates/scripts/aside-session.sh` — keeps one `aside repl` alive behind a FIFO so steps share variables and tabs (`start` / `send` / `stop` / `stop-under` / `list` / `account`; exit 2 = use the fallback, 3 = step failed or timed out). Background processes get no inherited stdio, and `stop` never blocks on a FIFO whose reader already exited. Installed with the exec bit (the installer now writes `*.sh` as 0755).
  - Installer (`src/installers/aside.js`, macOS only): installs the app with `brew install --cask aside`, opens it once when the background daemon (bundled in the app) has not been set up yet, and installs the `aside` CLI the way `releases.aside.com/install.sh` does — but downloads to a temp dir and requires `codesign --verify --deep --strict` plus Team ID `8CPD4K4TBB` before putting it in place, instead of `curl | bash`. New flags `--skip-aside` and `--aside-account <uN>` (validated); `--skip-scanners` also skips Aside.
  - `--doctor` gains an Aside check (warn only) that actually runs the CLI and confirms the test account exists — global doctor is now 11 checks.

- **`design-director` agent** — a fifth agent that decides a greenfield project's design direction and seeds `.cc-audits/design-profile.md`, so publisher has a system to enforce from screen 1. Two roles, deliberately separate: design-director decides **once per project** what the product should look like; publisher enforces that decision on **every** screen. Collapsing them back into one agent reintroduces the per-screen drift this stage exists to prevent. It runs a greenfield gate first (a profile, a design system, or any built screen → `not_applicable`, nothing written — inheriting an existing design stays publisher's job), classifies the lane (`product-ui` / `marketing-web`), shortlists exactly 3 candidates from the DESIGN.md catalog, and returns `next_action: user_interview`; the orchestrator interviews and re-calls it to commit the choice. It authors no production file.
  - `product-ui` is never routed to the optional `taste-skill` lane: that skill declares dashboards, dense product UI, admin panels, data tables, and wizards out of scope in its own §13 and instructs the agent to refuse them.
  - **Seeded-profile contract** (`reference_design_director_protocol.md` §7) — the one place the two agents share state and the one place it could silently break. publisher decides profile freshness by hashing `key_files`, but a seeded profile is written *before* those files exist, so a naive hash check would read `stale`, regenerate from an empty project, and erase the direction the user just chose, with no error. The seed is now marked `profile_origin: seeded` + `key_files: []` + `key_files_hash: null`, which publisher treats as a cache hit with no hash check; and any later regeneration must copy the `## Design Direction` section through verbatim — a scan can re-derive tokens from code, but not why a direction was chosen or what was rejected.
- `templates/memory/reference_web_interface_guidelines.md` — Vercel's Web Interface Guidelines (MIT © 2025 Vercel Labs), **vendored and pinned** to commit `e3d624ba`, wired into publisher's Step 5 self-check. The upstream skill fetches its rules over the network on every run, which makes the rule set a moving target: the same code reviewed twice can give different results, the gate needs network to work, and an upstream edit silently changes what the harness enforces — so the rules are pinned here instead, with a documented wholesale-refresh procedure. Overlap with axe-core is limited to a few a11y rules and duplicates are recorded once, with the runtime finding authoritative; the `Locale & i18n`, `Dark Mode & Theming`, and responsive sections are gated on the matching `quality_flags` so publisher does not flag scope it was told not to take on. - `templates/memory/reference_design_md_index.md` — a catalog of the 68 ready-made brand `DESIGN.md` files published at getdesign.md (indexed by [VoltAgent/awesome-claude-design](https://github.com/VoltAgent/awesome-claude-design), MIT), for picking a **greenfield** project's design direction. ### Fixed
Eight harness bugs found by the end-to-end smoke run in `docs/plans/harness-smoke-fixes.md` (a throwaway app built through every agent, hook and command, with planted defects as positive controls). Three of them (B4, B6, B8) failed **silently** — the component ran, did nothing, and `--doctor` still reported ok.

Reports are now `publish-<screen-slug>-iter-<n>.*` (new `screen_brief.screen_slug`, defaulting to the target file name), and screenshots go to `.cc-audits/<plan-slug>/screens/` instead of the project root.
- **B3** The E2E-guide hook relied on `"once": true`, which settings.json hooks do not honor — the ~16 KB guide was injected on **every** `mcp__playwright-test-*` call. It now keys a marker file on the hook's `session_id` and prints once per session (no session id → prints every time, the old behavior). The marker lives in a per-user `0700` directory and is created with `O_EXCL | O_NOFOLLOW`, so a pre-planted symlink cannot redirect the write.
- **B4** `security-auditor` let semgrep pick `--config auto`, which refuses to run with metrics off — semgrep was skipped on every audit. The agent now runs explicit rulesets with `--metrics=off` (JS/TS: `p/javascript` + the `insecure-document-method` rule, which the registry packs lack for `innerHTML` sinks; Python: `p/python`; else `p/default`) and records a failed run in `scanners_skipped` with its error.
- **B5** `/check-log` assumed `browser_network_requests` returns response headers and bodies; it returns neither, and only for the current page — so `Set-Cookie` never reached the masking step. Failed `GET`/`HEAD` requests are now replayed once with curl (marked "replayed") and redacted; non-idempotent requests are never replayed. Because the URL comes from the page under test, a replay requires a strict character allowlist, the same origin as the session URL, single-quoted `--url`, and `--max-time` / `--max-filesize`.
- **B6** `/clean` never stopped dev servers (background servers are re-parented to PID 1 and are not "claude" processes). It now stops TCP listeners whose cwd is inside the current **git root** (and refuses outside a repo or when the root is `/` or `$HOME`), skipping browsers and claude by executable name and playwright-mcp by its arguments, and deletes all `e2e-results/fail-*` files (screenshots were left behind).
- **B7** (a) Rule 6's `git add --all -- ':!.claude'` exits 1 once `.claude/` exists and is gitignored, breaking `&&` chains; the rule now uses `git add --all && git reset -q -- ':(top,glob)**/.claude/**'` (exit 0 whether or not `.claude/` is ignored, from any subdirectory, for nested `.claude/` dirs, and in a repo with no commits). (b) The path-policy hooks printed a deny decision and then exited 2, which Claude Code shows as a hook error; they now exit 0 and let `permissionDecision: deny` block.
- **B8** The SessionEnd orphan-cleanup hook matched `@anthropic-ai/claude-code`, which the native `claude` binary does not contain — it matched nothing and cleaned nothing. It now matches `pgrep -x claude` as well as the npm path, limited to the current user (`-u $(id -u)`) and skipping headless `claude -p` / `--print` runs, uses POSIX `[ ]`, and the new command prefixes are recognized as managed hooks.
- Regression tests for B3, B7b and B8 (the B3 test runs the hook twice with a temp `$HOME`) plus a guard that keeps the retired strings of B1, B2, B4 and B7a out of `templates/`; all five fail against the previous templates.

- Four more harness bugs from the second smoke run (harness-smoke v2), all in the browser layer:
  - **B9** The E2E-guide marker was keyed on the parent `session_id`, which subagents share — whichever agent touched Playwright first (publisher) consumed the guide and e2e-tester never got it. The marker is now keyed on `session_id` + `agent_id` (hook input carries `agent_id` / `agent_type` for subagents; the main session uses `main`), and the hook also fires for `aside repl` Bash commands while ignoring other Bash calls.
  - **B10** The §0-B dead-control sweep enumerated controls at load only, so a toast's close button calling an undefined function went unseen by both SWEEP and INVARIANTS. e2e-tester now records controls added later with a `MutationObserver`, clicks new ones right after each step (skipping re-rendered controls already swept), and reports any it could not reach as `transient-missed` instead of clean; the manager guide asks for explicit steps for known transient UI.
  - **B11** A tester saved its failure screenshot to the project root. Testers now receive `project_dir` and save only to `<project_dir>/e2e-results/fail-{N}-{ts}-<slug>.png` (absolute path), then check the root for strays.
  - **B12** `playwright-test-1` — the server `/open-browser` hands to the user — was `--headless`, so no window ever appeared and the user could not click anything. It is now headed in both the global and project templates (2–5 stay headless), and `--doctor` warns if it is still headless.
  - Regression tests for all four, each failing on the previous templates/code.
- Re-installing never updated a managed hook's **matcher**: `mergeHooks` replaced the hook in place inside its old entry, so a template matcher change (here `mcp__playwright-test-.*` → `mcp__playwright-test-.*|Bash`) silently kept the old one — and `--doctor` still reported the hook as registered. A managed hook whose template matcher differs is now removed everywhere and re-added under the new matcher (user hooks in the same entry are kept), and `--doctor` warns on `matcher out of date`.
